# FusionOps: extended architecture programme

Accepted scope extension from the supplied Ultimate Flagship Roadmap, 2026-10-13. This document records requested future work; it does not advertise completed capabilities. The active G1–G7 [foundation](flagship-vision.md), [delivery ledger](flagship-delivery.md) and [next implementation decisions](flagship-next-steps.md) remain intact. G3 is currently being implemented; G8–G30 below are unimplemented extensions. The additional fifteen research directions are retained, not silently discarded.

The extended objective is a C# platform for portfolio-wide planning, resource and supply authority, governed execution, cost evidence, historical reconstruction and bounded autonomous decisions. The commercial [pilot proposal](commercial-pilot.md) uses the same core with a narrower initial user journey; it does not replace the engineering programme.

## Delivery dependencies and proof gates

Each stage requires an owning module, versioned contracts, working API/storage where applicable, a concrete demonstration and independently inspectable verification. Dependencies are minimum prerequisites, not a claim that earlier foundations already implement the stage.

## Retained research directions beyond G30

These are requested research workstreams. Their implementation and proof scope must be made concrete as prerequisites land; a heading or prototype alone does not complete them.

| Workstream | Implementation question / acceptance direction |
| --- | --- |
| Proof-carrying plans | A versioned witness binds sources/constraints/solver result; an independent bounded verifier can accept/reject it without trusting search state |
| Live tenant migration | Move active tenant workflows with an ownership handoff; verify no old/new owner overlap and preserve provider-effect receipts |
| Constraint DSL | Bounded parser/type checker/evaluator with source-located errors and versioned rules; no arbitrary tenant code execution |
| Adaptive solver selection | Select a validated strategy from instance features and retained benchmark evidence; cancellation/fallback/quality claims stay valid |
| Decision provenance graph | Link facts, policies, baselines, approvals and effects across causal dependencies; traverse historical decisions under tenant authority |
| Economic scheduling | Scarcity prices and priorities produce inspectable resource tradeoffs while retaining hard budget and commitment authority |
| Workload-aware sharding | Measured repartitioning preserves routing/epochs/ownership during uneven load |
| Edge and IoT | Signed device observations, bounded offline queues, untrusted clocks and delayed readings; an observation does not imply resource ownership |
| Federated planning | Coordinate organizations using explicitly delegated shared-resource authority and limited disclosure; tenant isolation alone does not create federation |
| Region disaster simulator | Reproduce replication gaps, promotion and returning owners; evidence includes the applicable split-brain and RPO/RTO assumptions |
| Data governance | Versioned retention/export/deletion across stores/projections/backups with evidence and compatibility with retained financial/operational obligations |
| Workflow visual debugger | Inspect retained process/version/steps/timers/receipts and simulate recovery without replaying real effects |
| Architecture conformance | CI detects forbidden mutation paths and dependencies, including adapters bypassing authoritative admission |
| Causal incident analysis | Explanations follow recorded causal edges and distinguish proven causes from temporal correlation |
| Scenario marketplace | Versioned reusable models with provenance, permission checks, bounded evaluation and independent validation |

## Extended completion scenario

After the foundation scenario is proven, run portfolio-wide projects across organizations, sites and explicitly governed shared resources. Combine supplier delay, broken equipment, expired qualification and stale warehouse observation. Preserve committed/completed work while comparing cost and deadline alternatives. Let permitted changes pass a bounded policy and send other changes to a human approver.

Crash an execution worker after a participant confirmation, interrupt broker and one command store, then fail the authoritative region of a cell. Promote ownership through the documented protocol. On return, the former region cannot confirm another effect. Mission control reconstructs original decisions, leases, attempts, compensation and unresolved outcomes. Reconcile costs, quantities and ownership after recovery, retaining any genuinely unresolved ambiguity. Other cells remain operational.

Every report names workload/environment/protocol versions and measured scope. Additional deployments, AI or solver names are not substitutes for these results. A cell or region simulator is identified as a simulator; claims about real infrastructure require separately exercised deployments.

## Delivery order

Finish G3–G7 first. Then deliver portfolio/domain depth G8–G12, field/history/integration G13–G15, runtime and distributed authority G16–G23, twin/intelligence/autonomy G24–G28, and the extended operator/public experience G29–G30. Bring forward necessary contracts, such as source provenance and policy identity, while building the foundation. Each wave ends in a working lifecycle, with its limits and remaining work recorded.
